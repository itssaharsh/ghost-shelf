# T12 fresh-context review: Ghost Shelf

Reviewed read-only on 2026-10-19 (working tree at 17:01 UTC; Desk.tsx, Shelf.tsx, fixtures.ts, about/invented pages carry uncommitted edits, line numbers below are the working tree's). `npm test`: 39/39 pass. Live URL probed with 14 requests. No blockers against the seven hard constraints; the findings are product-correctness and write-up-honesty bugs.

## Findings, most severe first

1. **should-fix** `src/lib/collection.ts:63` - a title-only lookup returns null whenever the library holds two editions of the same book, so the catalog says "no record" for 59 held titles (136 rows: James, Intermezzo, Onyx storm, The wedding people, Rental house...). Scenario: type "Intermezzo" with no author; catalog answers "no record among 3,000 held titles", Open Library finds it, the card reads "Exists; we don't hold it." Fix: when no author is given, group `unique` by `authorKey(c.author)`; if there is one group, return its member with the highest `checkouts2025`.

2. **should-fix** `src/components/desk/Desk.tsx:310` and `src/app/api/log/route.ts:34` - the log posts the *current input fields* (`title`, `author`), not the checked run (`checkedRun.current`), and the server never checks that `runId` has `verdictKind === "no_record"`. Scenario: run "The Last Algorithm / Andy Weir", then retype the title field to "Dune" without pressing Check, press "Log this invented title": "Dune" enters the registry as an invented title. Same for holds at `Desk.tsx:281`. Fix: send `checkedRun.current`; in the route, `const run = await repo.getRun(runId); if (run?.verdictKind !== "no_record") return 409` (the contract's "registry accepts only titles a run found no record for").

3. **should-fix** `src/components/desk/Desk.tsx:98` (also `:90`, `:241`) - `recover()` has no run guard, so a late `/api/recover` response from run A overwrites run B's shelf. Scenario: click "Tidewater Dreams" (seeds, recover in flight ~1 s), immediately click "Nightshade Market" (no seeds, verdict fast, shelf set to zero books); A's response lands and three books appear under B's card with A's runId; Reserve then posts B's `runId` with A's ISBNs. Rapid seed add/remove has the same last-arrival-wins race. Fix: keep `currentRunRef`, and `if (json.runId !== currentRunRef.current) return;` before `setShelf`.

4. **should-fix** `src/lib/sources/internetarchive.ts:43` - with no author given, any archive text with the same title and *any* named creator counts as the book existing. Verified: `matchInternetArchive([{title:"The Last Algorithm", creator:"Random Student", date:"2019"}], {title:"The Last Algorithm"})` returns found, so the card says "Exists; we don't hold it. Internet Archive lists The Last Algorithm by Random Student" and the shelf is blocked ("Nothing to recover: the book is real", `Shelf.tsx:12`). The archive is full of user uploads. Fix: without an author require `d.isbn` or `d.publisher` on the doc, or downgrade an author-less archive hit to `titleOnlyBy` instead of `found`.

5. **should-fix** deployment - production runs with no `DATABASE_URL`: live `/api/holds` and `/api/registry?count=1` answer `"storage":"memory"`. On Fluid Compute each warm instance has its own `MemoryRepo`, so hold idempotency per run id (`src/db/memory.ts:36`), the registry count and `/api/request/last` depend on which instance answers; ARCHITECTURE.md:5,18 and ADR-0005 describe Neon as the datastore. The UI does label memory mode (`Desk.tsx:449`, `invented/page.tsx:13`). Fix: set `DATABASE_URL` on the Vercel project and redeploy, or state in the README that the live demo is memory-backed.

6. **should-fix** `src/app/api/recover/route.ts:30` and README.md:34-36,44 - the holdings gate (`filter.results.entities`, chunks of 150) and the holdings map that the README and "What makes it Qloo-powered" describe are never exercised: the route calls `recover(..., makeQlooClient())` with no `deps.entityMap`, so `heldEntityIds` is always undefined; `scripts/build-map.ts` (README:35) does not exist (`ls scripts/`). When it is wired, `src/lib/qloo/live.ts:119` runs the ~20 chunk calls sequentially (3,000 ids / 150) and `:104` resolves seeds sequentially: 20 x 6 s worst case against a "recovery under 3 s" target. Fix now: pass `entityMap: await getRepo().entityMap()` from the route and soften the README to "when the map is built"; later, `Promise.all` the chunks with a small concurrency cap.

7. **should-fix** `src/components/desk/PatronCard.tsx:70` - the "unchecked" card hard-codes "Our catalog, Open Library and Google Books did not answer", but without `GOOGLE_BOOKS_API_KEY` the third source is the Internet Archive (`check.ts:43`). Fix: build the sentence from the `sources` prop as line 11 already does.

8. **nit** `src/app/api/lists/route.ts:22` with `src/lib/recover.ts:120` - disliked *titles* are appended to `avoid` and matched by substring against every title and subject. "Didn't like: Us" removes every held title containing "us" ("The husbands"...), "It" removes most of the pool; the list can come back with fewer than five. Fix: word-boundary regex (`new RegExp(`\\b${escape(w)}\\b`, "i")`) and stop adding `disliked` to `avoid` (it is already handled by `dislikedToExcludes`).

9. **nit** `src/db/postgres.ts:20` - `ensureSeeded` caches a rejected promise forever: one cold-start Neon failure makes every later `registry()`/`logInvented()` reject until the instance recycles. Fix: `.catch((e) => { this.seeded = null; throw e; })`.

10. **nit** `src/app/api/check/route.ts:26` - the `error` SSE frame forwards `err.message` verbatim; a Neon failure in `upsertRun` (`:24`) would stream the driver's message (host, user) to the browser. Fix: send a fixed string and log the detail server-side.

11. **nit** `src/lib/normalize.ts:64` - `/^\d{10}$/` rejects ISBN-10s ending in X (`toIsbn13("080442957X")` is null), so an archive or Open Library record with only such an ISBN loses its isbn13. Fix: `/^\d{9}[\dXx]$/`.

12. **nit** docs that do not match the code (judges read these): ARCHITECTURE.md:5,11 and README:13 say the sources answer "in sequence" (they run concurrently, `check.ts:97`); ARCHITECTURE.md:55 says the per-instance rate limit is "stated in the README" (README has no mention) and "20/min/IP" (check is 30, cover 240, reads 120); ARCHITECTURE.md:55 "one retry on a Qloo 5xx" and `:61` "structured console logs ... an error boundary per page region" have no code behind them (no `console.*` in `src`, no `error.tsx`).

13. **nit** `src/lib/client/sse.ts:29` - on a mid-stream drop `readyState` is CONNECTING, so `onError` is not called and `es.close()` leaves the desk in "checking" with the inputs read-only (`Desk.tsx:404,412`). The uncommitted working tree adds a 12 s watchdog (`Desk.tsx:182` region) that covers this; HEAD does not. Commit it, or call `onError` whenever no verdict has arrived.

14. **nit** test gaps: no test for the two-edition title-only case (1), for `/api/log` after a non-no_record run (2), for the archive any-creator case (4; `tests/internetarchive.test.ts:24` only covers creator-less docs), for `/api/check` stream close on error and `runId` persistence, for `/api/recover` body validation, for the cover route id guard, or for `PostgresRepo` at all (parity with `MemoryRepo` is unverified).
